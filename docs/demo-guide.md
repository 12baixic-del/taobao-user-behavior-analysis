# 淘宝看板 · 3 分钟演示流程

看板启动方式（仓库根目录）：

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

浏览器打开后按以下顺序讲，每段约 30 秒。

## 0:00–0:30 · 开场与口径声明

页面顶部先讲三句话：数据来自阿里云天池 UserBehavior（与 Kaggle 公开镜像
同源验证通过）；样本是按 `user_id` 哈希整群抽样的 10,053 名用户
（总体 987,994 用户的 1.02%），窗口是北京时间 2017-11-25 至 12-03
（双 12 预热期 9 天）；原始数据无金额字段，只做 R+F（无 M）分析，
不涉及 GMV。顶部三个指标卡片：覆盖口径购买转化率 68.4%、完整路径
转化率 53.3%、次日留存 9 天简单平均 83.55%。

## 0:30–1:00 · 漏斗（双口径切换）

点 radio 切换两种口径。覆盖口径：浏览用户 9 天累计购买转化率 68.4%，
加购覆盖 74.4%、收藏覆盖 39.2%，两者并列展示、不设串联关系。
切到时序口径：浏览→意向 85.8%、意向→购买 62.2%，完整路径占浏览用户
53.3%；同时说明 22.1% 的购买用户为直接购买，不在该路径内——
“整体转化率 53.3%”只指完整路径，不能直接说成购买转化率。

## 1:00–1:30 · 每日趋势

日 PV 约 9.0–9.8 万（11-25 至 12-01），12-02/03 跃升至约 12.4 万；
购买转化率（按 PV）全程在 2.0%–2.4% 之间窄幅波动——流量跳升没有
拉动转化率，说明增长来自大促前夕的流量涌入而非转化效率提升。

## 1:30–2:15 · 次日留存

次日留存前 6 个值平均约 78.7%，后 2 个值平均约 98%（按报告口径表述为
工作日约 78.7%、周末约 98%）；周末的留存跃升与双 12 前夕流量涌入同步
出现。9 天简单平均 83.55%（pooled 84.24%），汇报时须注明是简单平均。

## 2:15–2:45 · R+F 分层

9 天内购买 ≥2 次的用户占 44.4%（4,467 人），购买 0 次占 31.9%；
“流失风险的高价值用户”为 0 人；R 维度在 9 天窗口内已退化
（99.86% 的用户 R=5），分层实际是单维 F——不得把“重要价值用户”
写成高价值客户占比，正确表述是“9 天内购买 ≥2 次”。

## 2:45–3:00 · Top 类目与收尾

流量最大的类目是 4756105（PV 44,450），但 Top 10 中购买转化率最高的是
4801426（1.31%）；流量最大的类目不等于转化最高的类目；类目无中文名，
仅以 `category_id` 标识。收尾一句话：样本口径下，购买转化用覆盖口径 68.4%，
留存拆工作日/周末，R+F 分层按“9 天内购买 ≥2 次”表述；完整方法与
核对见 REPORT.md，SQL 查询见 sql/。

## 常见问题

- **Top 类目图不显示**：样本文件 `outputs/taobao_clean_sample.csv`
  被 `.gitignore` 排除，仅用于本地复算；把该文件放回 `outputs/` 后刷新即可。
- **数字从哪来**：所有图表与指标卡片均在运行时从 `outputs/*.csv` 读取，
  代码中不硬编码任何业务数字。
